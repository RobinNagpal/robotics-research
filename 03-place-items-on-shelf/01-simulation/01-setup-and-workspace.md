# Phase 0 — Toolchain & ROS 2 workspace

> **Goal:** a reproducible machine and a ROS 2 workspace that can launch
> an empty Gazebo Harmonic world from a launch file. Get the plumbing
> right before any robot or store exists.
>
> **Checkpoint:** `ros2 launch <pkg> empty_world.launch.py` opens
> `gz sim` with a ground plane, and `ros2 topic list` shows bridged
> clock/topics.

---

## 0.1 Install the toolchain

On **Ubuntu 24.04**:

- **ROS 2 Jazzy** (`ros-jazzy-desktop`) — pulls in rviz2, tf2, the
  build tools.
- **Gazebo Harmonic** (`gz-harmonic`) — the `gz sim` simulator. On Jazzy
  this is the officially paired Gazebo version, so the matching `ros_gz`
  packages install cleanly from apt:
  - `ros-jazzy-ros-gz` (metapackage: `ros_gz_sim`, `ros_gz_bridge`,
    `ros_gz_image`).
- **Control + nav + motion stacks:**
  - `ros-jazzy-ros2-control`, `ros-jazzy-ros2-controllers`,
    `ros-jazzy-gz-ros2-control`
  - `ros-jazzy-navigation2`, `ros-jazzy-nav2-bringup`,
    `ros-jazzy-slam-toolbox`
  - `ros-jazzy-moveit`
  - `ros-jazzy-behaviortree-cpp` (or build BehaviorTree.CPP from source)

> If you must stay on Humble/22.04, Gazebo Harmonic is still usable but
> it is **not** the default pairing — set `GZ_VERSION=harmonic` before
> building `ros_gz` from source. Prefer Jazzy to avoid this.

Verify each independently before integrating:

- `gz sim shapes.sdf` opens the stock demo (simulator OK).
- `ros2 doctor` / `rviz2` launches (ROS 2 OK).

## 0.2 Workspace layout

One colcon workspace, packages split by responsibility so each maps to a
stack layer and can be reused on hardware unchanged:

```
shelf_ws/
  src/
    shelf_description/     URDF/SDF of the robot (Phase 2) + meshes
    shelf_worlds/          .sdf worlds + store/shelf/SKU/tray models (Phase 1)
    shelf_bringup/         launch files, bridge config, params, rviz configs
    shelf_navigation/      Nav2 params, maps, slam_toolbox config (Phase 3)
    shelf_moveit_config/   MoveIt 2 config, generated by Setup Assistant (Phase 4)
    shelf_grasp/           grasp logic + Gazebo attach/detach glue (Phase 4)
    shelf_perception/      geometric pose + slot finder nodes (Phase 5)
    shelf_orchestration/   Behavior Tree + ROS 2 action servers (Phase 5)
    shelf_msgs/            custom action/msg defs (job, place result, etc.)
```

Build with `colcon build --symlink-install`; source
`install/setup.bash`. Keep `shelf_bringup` as the single entry point —
everything launches through it.

## 0.3 The bridge config (the spine of sim↔ROS)

`ros_gz_bridge` translates Gazebo transport topics to ROS 2 topics. Put
**one** YAML bridge config in `shelf_bringup/config/bridge.yaml` and grow
it each phase. Minimal starting point:

```yaml
# clock so every ROS node can run on sim time
- gz_topic_name: "/clock"
  ros_topic_name: "/clock"
  gz_type_name: "gz.msgs.Clock"
  ros_type_name: "rosgraph_msgs/msg/Clock"
  direction: GZ_TO_ROS
```

Rules that save hours:

- **Always launch nodes with `use_sim_time:=true`** once `/clock` is
  bridged.
- Bridge only what you need; every topic is an explicit type mapping.
- Use `ros_gz_image` (not the generic bridge) for camera image topics —
  it is faster and handles `image_transport`.

## 0.4 First launch file

`shelf_bringup/launch/empty_world.launch.py` should:

1. Start `gz sim` with an empty world (via `ros_gz_sim`'s `gz_sim.launch.py`).
2. Start `ros_gz_bridge` with `bridge.yaml`.
3. (Optional) open rviz2 with a saved config.

## Deliverables

- `shelf_ws` builds clean with `colcon build`.
- `empty_world.launch.py` opens Gazebo + bridges `/clock`.
- A short `README` in `shelf_bringup` listing the launch entry points.

## Checkpoint

`ros2 launch shelf_bringup empty_world.launch.py` shows an empty world,
and `ros2 topic echo /clock` ticks. Plumbing proven — move to Phase 1.
